# Customer Communication Platform Onboarding Wizard

## Prerequisites

Before running this wizard, verify:

- **Shogun OS core installer (Steps 0–6)** has completed
- **Kizuna (CRM) profile** is created and its gateway is running
- **gbrain is initialized** (`gbrain doctor` passes)
- **At least 1 productivity suite** is connected (Gmail/M365 for contact sync)
- **Docker + Docker Compose** available (only needed for Chatwoot path)

If Chatwoot is desired but Docker isn't installed, this wizard handles it.

## Overview

This is a **Kizuna-specific post-install step**, NOT part of the core Shogun OS installer. It runs after the company has basic Hermes profiles for each department.

The wizard offers two paths:

```
┌─────────────────────────────────────────────────┐
│  Customer Communication Platform                │
│                                                 │
│  [a]  Respond.io (SaaS, paid, zero-infra)       │
│  [b]  Chatwoot (Open source, self-hosted, free) │
│  [c]  Skip (setup later)                        │
└─────────────────────────────────────────────────┘
```

## Wizard Steps

### Step 0: Freshness Check

Check if already configured:

```bash
# Check config
cat ~/.hermes/profiles/kizuna/config.yaml | grep -A5 "customer_communication"

# Check state
ls ~/.hermes/profiles/kizuna/state/cc-onboarding.json 2>/dev/null && echo "EXISTS" || echo "FRESH"
```

If already configured → show summary and exit.
If partial state exists → offer resume.

### Step 1: Platform Selection

| Option | Description | Cost | Infra Needed |
|--------|-------------|------|-------------|
| **a** | Respond.io | $79–279/mo | None (SaaS) |
| **b** | Chatwoot | Free (open source) | Docker host + domain |
| **c** | Skip | $0 | None |

Prompt the user:
> "Choose your customer communication platform:"
> **[a] Respond.io** — SaaS, paid (from $79/mo), no infrastructure, supports IG/FB/WA/Website/LINE. Best for teams that don't want to manage servers.
> **[b] Chatwoot** — Self-hosted, free, supports IG/FB/WA/Website/Email/SMS. Need a $5–10/mo VPS + domain. Best for teams wanting full control and no per-seat fees.
> **[c] Skip** — Set up later. Agents will only work via Telegram/Slack internally.

#### If Respond.io (branch A)
Go to **Step 2A**.
#### If Chatwoot (branch B)
Go to **Step 2B**.
#### If Skip
Write config with `enabled: false` and exit.

### Branch A: Respond.io Setup

#### Step 2A: API Credentials

Guide the user:
1. Log into [app.respond.io](https://app.respond.io)
2. Go to **Settings > API & Integrations > API Keys**
3. Click **Generate API Key**
4. Copy the key

```bash
# Store the key
mkdir -p ~/.hermes/profiles/kizuna/.secrets
echo "RESPONDIO_API_KEY=<paste-key>" >> ~/.hermes/profiles/kizuna/.secrets/secrets.env
chmod 600 ~/.hermes/profiles/kizuna/.secrets/secrets.env
```

Verify:
```bash
curl -s -H "X-API-Key: $(grep RESPONDIO_API_KEY ~/.hermes/profiles/kizuna/.secrets/secrets.env | cut -d= -f2)" \
  "https://api.respond.io/v2/workspace" | head -20
```

Expected: JSON with workspace name, contact count, etc.

#### Step 3A: Channel Inventory

Ask the user:
> "Which channels are you connecting through Respond.io? (comma-separated, or 'all')"
> - Instagram DM
> - Facebook Messenger
> - WhatsApp Business
> - Website chat widget
> - LINE
> - Telegram (already have Hermes — skip this)
> - Other

Map each channel to a **brain tag**:
```
channels: ig, fb, wa, web
```

Write to config:
```yaml
# ~/.hermes/profiles/kizuna/config.yaml
customer_communication:
  platform: respondio
  enabled: true
  channels:
    - ig
    - fb
    - wa
    - web
  webhook_secret: <auto-generated>
```

#### Step 4A: Configure Webhook

Set up the inbound webhook so Respond.io forwards messages to Hermes:

```bash
# Generate webhook secret
WEBHOOK_SECRET=$(openssl rand -hex 32)

# Register webhook with Respond.io
curl -s -X POST "https://api.respond.io/v2/webhooks" \
  -H "X-API-Key: $(grep RESPONDIO_API_KEY ~/.hermes/profiles/kizuna/.secrets/secrets.env | cut -d= -f2)" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://<kizuna-webhook-domain>/webhooks/respondio",
    "secret": "'$WEBHOOK_SECRET'",
    "events": ["message.created", "conversation.assigned", "conversation.closed"]
  }'
```

Write webhook secret to config:
```bash
# In config.yaml
sed -i "s/webhook_secret:.*/webhook_secret: $WEBHOOK_SECRET/" ~/.hermes/profiles/kizuna/config.yaml
```

#### Step 5A: Template Replies Scan

If the user already has template replies in Respond.io:
```bash
curl -s -H "X-API-Key: $RESPONDIO_KEY" \
  "https://api.respond.io/v2/templates" \
  | python3 -c "import sys,json; data=json.load(sys.stdin); [print(f'- {t[\"name\"]}: {t[\"body\"][:80]}...') for t in data.get('data',[])]"
```

Import into brain:
```bash
python3 ~/.hermes/skills/crm/respondio-bridge/scripts/import-templates.py
```

If no existing templates, ask:
> "What are your common reply templates? I'll store them in the brain."
> Let the user list them, or offer to import from existing conversations.

Creates brain pages at `~/brain/templates/respondio-*.md`

#### Step 6A: Agent Assignment Model

Ask:
> "How should conversations be assigned?"
> **[a] Hermes-first** — Hermes responds automatically. Escalates to a human when it can't handle the query or detects frustration.
> **[b] Human-first** — Conversations go to a human agent. Hermes suggests replies in the background.
> **[c] Co-pilot** — Hermes drafts replies, human reviews and sends.

Write to config:
```yaml
customer_communication:
  assignment_model: hermes-first  # or human-first, co-pilot
  auto_respond: true
  escalation_keywords:
    - "speak to a person"
    - "manager"
    - "complaint"
    - "refund"
```

#### Step 7A: Smoke Test

```bash
python3 ~/.hermes/skills/crm/respondio-bridge/scripts/test-integration.py \
  --api-key "$(cat ~/.hermes/profiles/kizuna/.secrets/secrets.env | grep RESPONDIO_API_KEY | cut -d= -f2)"
```

Expected output:
```
✓ API key valid (workspace: Acme Corp)
✓ Webhook reachable
✗ No test channel available — configure an inbox in Respond.io dashboard
```

Proceed to **Step 8** (Finalize).

### Branch B: Chatwoot Setup

#### Step 2B: Deploy Chatwoot

Check if Docker is available:
```bash
docker --version && docker compose version
```

If not, install Docker:
```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
newgrp docker
```

Deploy using the template:
```bash
cd ~/.hermes/profiles/kizuna/.infra/chatwoot
cp ~/.hermes/skills/crm/customer-communication-onboarding/templates/chatwoot/docker-compose.yml .
cp ~/.hermes/skills/crm/customer-communication-onboarding/templates/chatwoot/.env.example .env

# Generate secrets
sed -i "s/SECRET_KEY_BASE=.*/SECRET_KEY_BASE=$(openssl rand -hex 64)/" .env
sed -i "s/FRONTEND_URL=.*/FRONTEND_URL=https://chatwoot.yourdomain.com/" .env

docker compose up -d
```

Wait for healthy:
```bash
sleep 30 && docker compose ps
```

Expected: `chatwoot-web` and `chatwoot-worker` should be `Up (healthy)`.

Guide the user through **Chatwoot admin setup**:
1. Visit `https://chatwoot.yourdomain.com` (or `http://<server-ip>:3000` for local-only)
2. Create admin account (email + password)
3. Accept default settings

#### Step 3B: Create Inboxes

Ask the user:
> "Which channel inboxes do you need in Chatwoot?"
> Same channel list as Step 3A.

For each channel, guide through Chatwoot's native inbox creation:

| Channel | Chatwoot Setup |
|---------|---------------|
| **Website** | Settings → Inboxes → Add → Website → Paste widget code |
| **WhatsApp** | Settings → Inboxes → Add → WhatsApp → Link WABA account |
| **Facebook Messenger** | Settings → Inboxes → Add → Facebook → FB Login |
| **Instagram DM** | Settings → Inboxes → Add → Instagram → IG Login |
| **Email** | Settings → Inboxes → Add → Email → SMTP/IMAP config |

Alternative: Use Chatwoot API to script inbox creation:
```bash
python3 ~/.hermes/skills/crm/customer-communication-onboarding/scripts/create-chatwoot-inboxes.py \
  --api-url "http://localhost:3000" \
  --access-token "$CHATWOOT_TOKEN" \
  --channels ig,fb,wa,web,email
```

#### Step 4B: Wire Webhook to Hermes

Configure Chatwoot to forward messages to Kizuna:

```bash
# Generate webhook secret
WEBHOOK_SECRET=$(openssl rand -hex 32)

# Register in Chatwoot
curl -s -X POST "http://localhost:3000/api/v1/webhooks" \
  -H "api_access_token: $CHATWOOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://<kizuna-webhook-domain>/webhooks/chatwoot",
    "secret": "'$WEBHOOK_SECRET'"
  }'
```

Write to config:
```yaml
# ~/.hermes/profiles/kizuna/config.yaml
customer_communication:
  platform: chatwoot
  enabled: true
  chatwoot:
    api_url: "http://localhost:3000"
    access_token: "<stored in .secrets>"
    webhook_secret: <auto-generated>
    inboxes:
      - type: website
        id: 1
      - type: whatsapp
        id: 2
      ...
```

#### Step 5B: Agent Accounts

Create Chatwoot agent accounts for each Kizuna team member:

```bash
python3 ~/.hermes/skills/crm/customer-communication-onboarding/scripts/create-chatwoot-agents.py \
  --api-url "http://localhost:3000" \
  --access-token "$CHATWOOT_TOKEN" \
  --agents-file ~/brain/people/  # reads brain people pages
```

Creates Chatwoot accounts for each person with `kizuna` tag in brain, sends welcome email.

#### Step 6B: Agent Assignment Model

Same as Step 6A — ask the same question about Hermes-first / Human-first / Co-pilot.

#### Step 7B: Smoke Test

```bash
python3 ~/.hermes/skills/crm/chatwoot-bridge/scripts/test-integration.py \
  --api-url "http://localhost:3000" \
  --access-token "$CHATWOOT_TOKEN"
```

Expected output:
```
✓ Chatwoot API reachable
✓ Webhook endpoint registered
✓ Can create test conversation
✓ Can send test message
✓ Can receive test message
```

Proceed to **Step 8**.

```yaml
customer_communication:
  platform: <respondio|chatwoot>
  enabled: true
  assignment_model: <hermes-first|human-first|co-pilot>

    - <list from step 3>

    ig: inbox_ig      # respond.io channel name / chatwoot inbox id
    fb: inbox_fb
    wa: inbox_wa
    web: inbox_web
  escalation_keywords:
    - "speak to a person"
    - "manager"
    - "complaint"
```


## Trigger Integration with Core Shogun Installer

The core Shogun OS installer's Step 4 (Department Selection) creates the Kizuna profile. At the end, instead of inlining this wizard, it should say:

> "Kizuna profile created! To set up your customer communication platform (shared inbox for IG/FB/WA/Website), run:
> `hermes -p kizuna -q 'cc setup'`"

This keeps the core installer lean and makes the CC onboarding self-contained.
